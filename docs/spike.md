# 0단계 결과: 에디터 검증

작성일: 2026-10-05
기준: TurboWarp/scratch-gui `1e08e6a` (develop, 2026-10-04), Node 26.4, macOS, Playwright 크로미움(헤드리스)

0단계의 확인 항목은 모두 가능하다. 다른 출처의 시험 페이지에서 에디터를 iframe으로 띄워 자동 점검 20개를 돌렸고 전부 통과했다. 설계를 바꿔야 할 만큼 막힌 항목은 없고, 결정이 필요한 것이 2개, 1단계에서 처리할 것이 7개 나왔다.

실제 학원 PC에서의 성능 측정은 하지 못했다. 아래 수치는 개발용 맥에서 CPU를 6배 느리게 한 추정치다.

## 성능

개발용 맥에서 잰 값이다. 학원 PC와 크롬북의 실측은 아니다.

| 측정 | 보통 | CPU 6배 감속 |
| --- | --- | --- |
| 페이지 이동부터 `ready`까지 (캐시 없음, 로컬 서버) | 0.9초 | 4.3초 |
| 동적 검사 1개 (키 200ms + 대기 500ms) 전체 시간 | 0.78초 | 0.80초 |
| 그중 두 번째 실행 환경을 만들고 작품을 불러오는 시간 | 10ms | 57ms |
| 채점 중 에디터 화면의 가장 긴 프레임 간격 | 측정 안 함 | 33ms (100ms 넘는 프레임 0개) |

채점 시간은 거의 전부 액션이 정한 대기 시간이고, 실행 환경을 만들고 없애는 비용은 작다. 시험에 쓴 작품은 스프라이트 1개에 스크립트 2개짜리라, 모양과 소리가 많은 작품에서는 불러오는 시간이 더 걸린다. 실제 네트워크에서는 7MB 스크립트의 다운로드 시간이 더해진다.

## 결정이 필요한 것

1. **스프라이트·소리 라이브러리는 스크래치의 서버에서 불러온다.** 라이브러리를 열 때 썸네일을 `cdn.assets.scratch.mit.edu`에서, 스프라이트를 추가할 때 파일을 `assets.scratch.mit.edu`에서 받는다. 학원 네트워크에서 두 주소가 열려 있어야 하고, 스크래치 쪽 서버 상태에 영향을 받는다. 그대로 쓸지, 라이브러리 파일을 에디터와 같은 서버에 올려 둘지 정해야 한다. 한 번 추가한 스프라이트는 sb3 안에 들어가므로 저장과 채점은 이 서버와 무관하다. (1단계 전)
   → **결정(2026-10-19): 스크래치 서버에서 그대로 불러온다.** 소리와 배경 라이브러리도 같은 서버를 쓴다(1단계 점검 19).
2. **메뉴 바 색.** TurboWarp의 기본 강조색은 빨강이다. 목업의 보라(`#855CD6`)는 TurboWarp에 내장된 보라 테마로 맞출 수 있다. 저장 버튼의 모양은 직접 만든 것이라 목업대로 조정할 수 있다. 테마 선택 메뉴를 숨기고 보라로 고정할지 확인이 필요하다. (1단계 전)
   → **결정(2026-10-19): 보라로 고정하고 테마 메뉴를 숨긴다.** 1단계에서 반영했다.

## 처음 설계와 달라지는 점

- **채점용 실행 환경에는 렌더러를 반드시 붙인다.** 렌더러 없이 실행하면 무한 반복이 화면 갱신을 기다리지 않고 돌아, 0.7초 동안 y좌표가 460만까지 올라갔다(렌더러를 붙이면 36). 학생 화면과 같은 속도로 실행하려면 보이지 않는 캔버스에 렌더러를 붙여야 하고, 닿았는지 검사에도 렌더러가 필요하다. 붙여도 생성·제거 비용은 위 표와 같이 작다.
- **블록 id는 저장할 때 바뀐다.** TurboWarp가 내보낼 때 id를 짧게 다시 붙인다. 채점 규칙은 opcode로 판별하므로 영향이 없지만, id에 기대는 기능은 만들 수 없다.
- **저장 버튼은 스크래치의 것을 켜는 방식이 아니다.** TurboWarp가 서버 저장 UI를 파일 다운로드로 바꿔 놓아 켤 수 있는 설정이 없다. 같은 자리에 우리 컴포넌트를 넣는 패치(2줄)로 해결했다. 메시지 `saveRequested`, `setSaveStatus`는 설계대로 동작한다.
- **기본 프로젝트의 캐릭터는 스크래치 고양이가 아니다.** TurboWarp의 자체 캐릭터가 들어 있다. Scratch 로고와 고양이를 마스코트로 쓰지 않는다는 원칙에 맞는다.

## 1단계에서 처리할 것

1단계에서 모두 처리했다(README와 `test/bridge-check.mjs`). 단, `view` 모드의 편집 막기는 보류했다(아래 항목 참고).

- `loadProject`의 `sb3: null`(빈 프로젝트). 0단계에서는 구현하지 않았다.
- 확장 라이브러리의 "사용자 확장" 항목 제거와, 파일·주소·코드로 확장을 넣는 경로 차단 확인.
- 메뉴 바에서 "TurboWarp 문의하기", "고급 설정", 테마 메뉴, 애드온 제거.
- 에디터가 iframe 높이를 다 채우지 않는다(900px 중 약 640px). 감싸는 요소의 높이 지정이 필요하다.
- `view` 모드에서 저장 버튼은 숨겨지지만 편집은 그대로 된다. 고친 내용이 저장되지 않는 것은 호스트 사이트가 저장 요청을 하지 않아서이며, 에디터가 막는 것은 아니다.
- 브리지를 `protocol.ts` 타입 정의에 맞춰 다시 쓴다. 지금의 `editor/bridge.js`와 `editor/grader-spike.js`는 검증용이다.
- 자동 점검이 `window.__studioVm`으로 VM에 직접 접근한다. 실제 빌드에서는 없앤다.

## 하지 못한 것

- 학원에서 가장 사양이 낮은 PC와 크롬북에서의 로딩 시간과 채점 중 버벅임 실측. 위 수치는 추정치다. `npm run serve`로 띄운 시험 페이지를 해당 기기에서 열면 같은 방법으로 잴 수 있다.
- 소리 라이브러리와 배경 라이브러리의 요청 서버는 따로 확인하지 않았다(스프라이트 라이브러리만 확인). → 1단계에서 확인했다. 둘러볼 때는 `cdn.assets.scratch.mit.edu`(소리는 요청 없음), 추가할 때는 `assets.scratch.mit.edu`다.
- 사파리와 파이어폭스. 크로미움만 확인했다.
